-----------------------------------
 Project Moto Trip Dates
-----------------------------------

Этот международный проект представляет собой высоконагруженную SaaS-платформу для мотопутешественников, объединяющую
функции комьюнити-билдинга, дейтинга (поиска попутчиков) и дорожной безопасности.

Проект спроектирован по принципам предметно-ориентированного проектирования (DDD) и Гексагональной архитектуры (Ports
and Adapters) в виде модульного монолита, который готов к безболезненному разделению на микросервисы при росте
международной нагрузки.

🛠️ Стек технологий (Tech Stack)

Проект использует современный гибридный стек на Java 17 для максимальной производительности:
- Ядро платформы: Java 17, Spring Boot 3.4.2, Maven.
- Блокирующий стек (CRUD): Spring Data JPA (Hibernate) — обеспечивает надежную работу с транзакционными данными
(пользователи, анкеты, мэтчи).
- Неблокирующий реактивный стек (High Load): Spring WebFlux, R2DBC — используется для обработки потоков гео-координат в
реальном времени и WebSocket-сообщений, чтобы не блокировать потоки процессора.
- База данных: PostgreSQL с расширением PostGIS для выполнения сложных пространственных запросов (гео-индексация GIST)
и вычисления координат на картах.
- Брокер сообщений: Apache Kafka — для асинхронного event-driven взаимодействия, распределения WebSocket-сессий и
мгновенной веерной рассылки экстренных SOS-сигналов.
- Хранилище медиа (S3): Локальный MinIO в Docker (с полной совместимостью с AWS SDK) для хранения галереи фотографий
пользователей.
- Инфраструктура: Docker, Docker Compose (для развертывания баз, Kafka, MinIO и самого приложения одной командой),
Flyway (автоматические миграции БД).
- Фронтенд (перспектива): React SPA (с интеграцией интерактивных карт Leaflet/Google Maps и анимацией спецэффектов).

🧠 Логика и ключевые модули проекта

Платформа разделена на изолированные функциональные домены:

1. Модуль пользователей и мото-анкет (users, riders, user_photos)
- Авторизация: Безопасный доступ по паре JWT-токенов (Access/Refresh) с возможностью отзыва сессий (revoked) и аудитом
по IP/User-Agent.
- Разделение ролей: Базовый аккаунт (users) расширяется специализированной мото-анкетой (riders). Пользователи делятся
на водителей (DRIVER со своим байком), пассажирок (PASSENGER, желающих кататься «двойкой») и попутчиков (COMPANION).
- Галерея (Tinder-style): Таблица user_photos с полем display_order позволяет загружать пачки фото в S3/MinIO и
настраивать их порядок для отображения в дейтинг-ленте.

2. Модуль Дейтинга и Мэтчинга (matches, blocks)
- Свайпы и логика мэтча: Пользователь свайпает карточки. При отправке лайка система проверяет наличие встречного
запроса. Если он есть, статус меняется на MATCHED, что мгновенно триггерит неоновую вспышку 💥 на фронтенде и открывает
доступ к чату.
- Безопасность: Таблица blocks полностью исключает нежелательных пользователей из поисковой выдачи и запрещает им
отправку сообщений.

3. Модуль общения и Мотобратств (chats, messages, brotherhoods)
- Полиморфные чаты: Единая архитектура сообщений поддерживает диалоги для дейтинга, групповые чаты для участников
совместных поездок и приватные каналы для мото-клубов.
- Иерархия братств: Поддержка создания байкерских клубов со строгой модерацией заявок на вступление и ролевой моделью
внутри сообщества (Президент, Офицеры, Райдеры).

4. Высоконагруженный Гео-трекинг (rider_locations)
- Изоляция телеметрии: Динамические GPS-координаты движущихся мотоциклистов вынесены в отдельную узкую таблицу
rider_locations. Это исключает блокировки строк в основной таблице профилей при постоянных апдейтах.
- Эффекты на карте: Смартфон стримит координаты на WebFlux -> бэкенд вычисляет направление движения (bearing) и пушит
данные другим юзерам по WebSockets, позволяя рисовать кастомные анимации (например, дым из-под колес 💨) на картах
React.

5. Экстренная помощь (SOS Маяки)
- Алгоритм спасения: При нажатии кнопки SOS, POST-запрос фиксирует точку происшествия в таблице sos_alerts. Событие
летит в Kafka. Гео-сервис делает мгновенный запрос через PostGIS-индекс GIST в таблицу активных локаций, находит всех
байкеров в радиусе 100 км и веером рассылает им экстренные Push-уведомления с точными координатами беды.

Этот проект идеально демонстрирует мои навыки как Архитектора и Тимлида: проектирование сложных распределенных систем,
работа с гео-данными под высокой нагрузкой и создание масштабируемого SaaS-продукта.
